# 项目目录模型

本文件描述本工作流使用的最小目录分层，只覆盖长期文档和临时计划两层。

## 目标

- 让人和 AI 都能快速定位当前有效规则。
- 让当前需求的临时计划有固定落点，便于整理和执行。
- 把长期规则和当前任务分开，避免混淆。

## 推荐结构

```text
.
├── README.md
├── AGENTS.md
├── CLAUDE.md
├── docs/
│   ├── README.md
│   ├── context/
│   ├── standards/
│   ├── runbooks/
│   └── adr/
├── plans/
│   └── YYYY-MM-DD-<slug>/
│       ├── plan.md
│       └── tasks.md
└── src/
    └── <module>/
        └── README.md
```

并非所有目录都必须创建。按真实内容创建，不为完整性制造空目录。

## 主真源速查表

| 信息类型                                 | 推荐主真源                 |
| ---------------------------------------- | -------------------------- |
| 项目入口、安装启动、常用命令             | `README.md`                |
| 模块职责、关键流程、局部包袱、常见坑     | 模块 `README.md`           |
| Agent 操作约束、高风险区域、验证要求     | `AGENTS.md`                |
| Agent 本地流程、模板、脚本、命令适配     | `.agents/`                 |
| 项目级长期规则、跨模块边界、通用业务口径 | `docs/`                    |

补充判断：

- `/lite:knowledge` 不应因为用户提到文档或 `docs/` 就把所有知识集中写进 `docs/`。
- 当知识明显属于模块上下文时，应优先写对应模块 `README.md`。
- 当知识是项目级运行机制、跨模块链路或全局约束时，优先写 `docs/` 下聚焦的主题文档。

## docs/ 可选分层

当某条知识已经确定应沉淀到 `docs/` 时，优先继续判断子目录，而不是统写到根目录。以下子目录仅在内容明显属于该类、且后续会持续复用时再创建：

| 路径 | 用途 | 何时创建 |
| --- | --- | --- |
| `docs/context/` | 项目背景、业务上下文、历史约束 | `README.md` 背景逐渐过长，或需要长期保留业务前情时 |
| `docs/standards/` | 项目特有工程规范、目录边界、字段口径、协作约定 | 规范已经超过 `README.md` 合理体量，且会持续约束后续实现时 |
| `docs/runbooks/` | 发布、回滚、排障、环境操作、联调流程 | 流程需要复用、交接、值班或故障处理中反复查阅时 |
| `docs/adr/` | 长期架构决策、关键取舍、废弃方案 | 设计决策需要追溯“为什么这样做”时 |

如果内容规模还小、语义还不稳定，或项目尚未形成明确分层，也可以先沉淀在 `docs/README.md` 或 `docs/` 下现有更贴切的文件中，不必为了分类而新建目录。

## `/lite:knowledge` 常见落点组合

全项目知识采集时，常见结果不是“只生成一个文件”，而是以下组合之一：

- `docs/README.md` + `docs/` 下 1 到 3 个主题文档
- `docs/` 下若干主题文档 + 1 到多个模块 `README.md`
- 轻量更新 `README.md` 或 `AGENTS.md` 的入口摘要，同时把长内容归位到 `docs/` 或模块 `README.md`

如果一次采集得到的知识天然分成多束，例如“运行时与环境”“请求与鉴权”“路由与菜单”“复杂模块包袱”，优先拆成多份聚焦文档，而不是压成一份总说明。

## 两层结构

### 长期文档层

主位置：

- `README.md`
- `AGENTS.md`
- `docs/` 下合适的长期文档
- 模块 `README.md`

用途：

- 当前系统行为
- 业务规则
- 接口契约
- 跨模块流程
- 工程约定
- 高风险修改点
- 长期背景与决策记录

### 临时计划层

主位置：

- `plans/YYYY-MM-DD-<slug>/`

用途：

- 当前需求的整理稿
- 工单、资料链接、评审结论和补充上下文的汇总
- 任务拆分
- 待确认问题
- 实现计划
- 验收点

## 快速规则

- 长期稳定规则写进长期文档层。
- `AGENTS.md` 是默认项目级 Agent 规则入口；`CLAUDE.md` 作为兼容入口默认也应存在，并优先通过 `@AGENTS.md` 指向同一份规则，而不是维护独立内容。
- 本次需求推进材料写进临时计划层。
- 若项目已有 `OpenSpec` 或 `Superpowers` 的计划体系，则该体系才是当前项目的计划主真源；`lite-spec` 不应再额外引入一套并行 `plans/`
- 任务完成后，把仍然长期有效的规则回写到 `docs/` 下合适的位置、模块 `README.md`，或其他长期主真源。
- `docs/` 子目录按语义和复用频率按需创建，不为“看起来完整”而预建目录。
- `plans/` 默认视为临时工作区，不作为长期主真源；需求完成后可删除或归档。
- 对 `/lite:knowledge` 而言，“归位正确”优先于“都写进 `docs/`”；主真源判断先于目录创建。
