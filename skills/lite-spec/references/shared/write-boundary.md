# 写入边界

本文件用于约束：哪些信息可以沉淀到目标项目，哪些信息只能作为本次执行的上层指导，不得直接写入项目文档。

## 可写入目标项目的信息

- 目标项目已有文件中已经存在、且可被直接读取或引用的项目事实。
- 用户明确要求写入、且语义清楚的项目信息。
- 从代码、配置、脚本、命令输出、长期文档或外部资料正文中验证出的项目特异信息。
- 已经在当前需求中被确认、并且未来仍然稳定有效的规则、边界和约定。

## 默认不得直接写入目标项目的信息

- 当前会话中的 system / developer 指令。
- 全局 `AGENTS.md` 或团队公共层规则原文。
- 用户长期偏好、当前工具行为准则、模型侧工作风格说明。
- 当前执行机器的绝对路径、用户目录、盘符路径或其他仅对本机成立的路径信息。
- 尚未验证的推断、联调猜测、临时讨论结论。

## 引用团队公共规则时的处理方式

- 可以写“参照团队公共规范”这类简短引用。
- 不要把团队公共规则整段复制进项目文档。
- 若项目对团队规则存在特例，只写项目特有的偏差或补充。

## 可信度要求

- `已验证`：来自代码、配置、命令输出、外部资料正文或用户明确确认。
- `推断`：根据上下文合理推断，但尚未被直接确认。
- `待验证`：写成事实前必须再次核实。

未验证内容不能直接写成项目事实；应至少标记为 `推断` 或 `待验证`，并说明来源。
