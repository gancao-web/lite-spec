# /lite:plan States

`/lite:plan` 运行后，AI 应明确落在以下状态之一，并按对应方式输出。

## State A: External Planning Framework Mode

适用条件：

- 目标仓库已经明确采用 `OpenSpec` 或其他稳定规划框架
- 或仓库已经有另一套稳定的计划 / task 主真源，若继续生成 `lite-spec` 的 `plan.md`、`tasks.md` 会造成双轨主真源

输出要求：

- 明确指出当前项目已有哪套规划框架
- 继续使用 `/lite:plan` 做上下文梳理、外部资料访问、风险识别和必要澄清
- 不生成 `lite-spec` 的 `plan.md`、`tasks.md`
- 不创建额外的 `plans/` 工作区
- 最终计划、任务或变更说明写入项目原有规划体系的主真源，并遵循其模板、命名和状态流转
- 若原规划体系的文档位置、模板或状态流转不明确，先读取仓库现有文档和示例；仍无法判断时再向用户确认
- 若用户当前真实诉求是访问资料、初始化长期文档或沉淀知识，则提示可继续使用 `/lite:open`、`/lite:init`、`/lite:knowledge`

## State B: Blocked: Credentials

适用条件：

- 外部资料需要访问
- `/lite:open` 判定所需凭证缺失、失效，或当前没有可用访问方式

输出要求：

- 明确指出缺少哪类凭证
- 停止后续计划生成
- 不进入代码实现

## State C: Blocked: Clarification

适用条件：

- 资料可访问
- 但需求存在关键歧义，继续生成 task、写入外部规划体系或直接落代码会影响实现方向
- 命中了 `references/plan/clarification.md` 中的高优先级问题，且用户尚未确认
- 或者在非直做模式下，当前待确认项总数只有 1 到 2 个，尚未向用户逐项确认
- 当前无法把歧义合理降级为非阻塞项

输出要求：

- 默认提出 1 到 3 个高价值澄清问题；若阻塞性歧义较多，可扩展到 4 到 5 个；若超过 5 个，则分批确认
- 非直做模式下，当待确认项总数只有 1 到 2 个时，应全部先提问确认，不得直接带着这些待确认项进入 `Plan Ready`
- 直做模式下，只阻塞影响实现方向、模块/服务落点、接口契约、数据结构、交互主流程、验收标准或会导致明显返工的分歧；低优先级非阻塞分歧可按项目惯例决策后继续实现
- 能给选项时直接给选项
- 暂不生成最终 task
- 暂不进入 `Plan Ready`

## State D: Plan Ready

适用条件：

- 资料足够
- 凭证齐全
- 关键歧义已解决或可控
- 非直做模式下，待确认项若只有 1 到 2 个，必须已完成逐项确认
- 不存在未解决的高优先级阻塞性澄清问题
- 已生成默认模式的 `plan / tasks`，或已按项目原有规划体系生成对应计划 / task / 变更说明

输出要求：

- 告知产物路径，并仅使用仓库相对路径
- 引导用户先审核对应计划与任务产物；默认模式下是 `plan.md` 与 `tasks.md`，外部规划体系模式下是项目原有规划体系的产物
- 明确未批准前不进入代码实现，也不继续执行计划中的任务

## State E: Ready for Direct Build

适用条件：

- 用户已明确要求直接实现、直接改代码，或不要生成计划 / 任务
- 资料足够
- 凭证齐全
- 不存在未确认的阻塞性分歧
- 低优先级非阻塞分歧已按项目惯例形成合理默认

输出要求：

- 不生成 `plan.md`、`tasks.md`
- 不创建 `plans/` 工作区
- 直接进入代码实现
- 最终说明中标注关键默认决策或假设

## State F: Approved for Build

适用条件：

- 用户已明确确认按计划实现

输出要求：

- 允许进入代码实现
- 继续按对应计划 / 任务产物推进；默认模式下是 `plan / tasks`，外部规划体系模式下是项目原有规划体系的产物
