# 模板

以下模板是起点，不是强制填满的表格。生成内容时保持短、具体、项目特异。

模板中的“路径”“目标位置”“项目根目录”等字段，默认都使用仓库相对路径、`.` 或仓库名；不要写入带盘符或用户目录的绝对路径。

## 最小 AGENTS.md

```md
# AGENTS.md

## 入口规则

- 包管理器和常用命令以 `README.md` 和 lockfile 为准。
- 修改业务行为前，先阅读 `README.md`、相关长期文档、模块 README 和关键注释。
- 修改复杂模块前，如模块目录存在 `README.md`，先阅读该文件。

## 主真源约定

- 面向人的项目介绍、安装方式、目录导航以 `README.md` 为准。
- 长期业务规则、模块边界和可复用约束以 `docs/` 下相关文档为准。
- 模块内局部实现说明以模块目录 README 和代码注释为准。
- 单次需求的整理稿、待确认项和任务拆解应写入按需创建的 `plans/` 临时工作区，不作为长期主真源。

## 高风险区域

- 不要直接编辑生成代码；按对应生成流程更新。
- 修改请求层、权限层、路由层、埋点层、支付、审批流或核心配置前，需要说明影响范围和验证方式。

## 验证要求

- UI 行为变更至少运行受影响模块测试，或手工验证关键路径。
- 依赖、构建、请求、权限、部署相关变更需要补充验证结果。
```

## docs/README.md

```md
# docs

本目录存放项目长期文档。

## 目录约定

- `context/`：项目背景、业务上下文、历史约束；仅在背景说明超过 `README.md` 规模时创建。
- `standards/`：项目特有工程规范、目录边界、字段口径、协作约定；仅在规则需要长期复用时创建。
- `runbooks/`：发布、回滚、排障、环境操作；仅在流程会反复复用时创建。
- `adr/`：长期架构决策与关键取舍；仅在决策需要追溯时创建。
- 若项目仍较小，可先直接在 `docs/` 根目录维护少量长期文档，不必预建完整子目录。

## 当前内容

- `path/to/doc.md`：一句话说明该文档承载的长期知识。
```
