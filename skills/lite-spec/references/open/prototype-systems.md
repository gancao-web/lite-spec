# 原型系统专项规则

用于补充 `/lite:open` 在 Axure 及其他原型系统场景下的强制解析规则。

## 适用范围

- Axure 导出原型
- 其他具备播放器页、导出目录、页面 html、资源脚本或图片标注结构的原型系统

## 强制规则

1. 若外层播放器页可打开，但主区域是 `iframe` 且 `src="about:blank"`，不能据此判定“正文不可读”
2. 必须继续解析该原型导出的机器可判定资源，例如 `data/document.js`、sitemap、真实页面 html（如 `页面.html`）以及页面级 `files/<page>/data.js`
3. 解析真实页面 html 时，优先提取页面中真实可见的文案节点、输入框值、表头和按钮文本，不要把样式名、字体名等导出噪音当成正文
4. 若在页面 html 或导出资源中识别到图片资产，必须优先尝试生成浏览器整页截图，供后续 AI 直接阅读；`og:image` 或页面缩略图仅作辅助入口或兜底
5. 图片资产的结构化信息仅作为辅助线索，例如 `widgetId`、类型、URL、局部文本与标记信息；用于区分标注图、装饰图和正文相关图片，但页面理解仍以最终渲染截图为主，不要把单张素材图、切片图、图标资源当成正文来源
6. 若在页面 html 或导出资源中未识别到图片资产，且静态 html 已能完整提取正文、表格、表单和按钮文本，则通常不需要额外截图
7. 若静态 html 提取结果过少或明显缺失，再使用浏览器 DOM 兜底采集一次真实渲染后的页面正文；若仍不足，则应把最终渲染页截图作为 AI 复核输入
8. 只有在这些导出资源、真实页面与最终预览图都无法解析出目标页面时，才可判定当前原型正文不可读

## 建议解析顺序

1. 先确认结构化入口，例如导出目录、页面清单、元数据脚本
2. 再解析目标页面 html 与页面级资源脚本
3. 若在页面 html 或导出资源中识别到图片或标注资产，补齐图片结构；并优先尝试生成最终渲染预览图或页面截图
4. 若静态结果不足，再定位最终渲染预览图或页面截图，并将其作为 AI 直接阅读的证据
5. 若仍不足，再使用浏览器 DOM 作为兜底
6. 仅在上述步骤都失败后，才判定当前原型正文不可读

## 输出要求

- 明确区分“播放器页可打开”和“目标页面正文可读”这两个结论
- 明确说明已使用的解析入口，例如 `document.js`、页面 html、`files/<page>/data.js` 或浏览器 DOM
- 若提供了最终预览图或页面截图，必须明确说明这是给后续 AI 直接阅读的视觉证据
- 对图片仅输出可证实的结构化信息；不因字段预留而猜测业务语义
